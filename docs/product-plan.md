> 版本：v0.2 | 最後更新：2026-06-02
> 狀態：草案 — 待確認

---

## 1. 專案概述

| 項目 | 內容 |
|------|------|
| 專案名稱 | TarotWise |
| 平台 | Web 響應式 (Responsive)，以 Mobile-first 設計 |
| 目標用戶 | 一般大眾，特別考量年長使用者 |
| 核心價值 | 隨時隨地抽牌、AI 智慧解牌、記錄心靈軌跡 |

### 設計原則（年長用戶友善）

- **大字體**：基準字體 18px 以上，可切換至更大
- **大觸控區域**：按鈕/輸入框最小 48x48px
- **簡潔版面**：一頁只顯示一個核心功能，細節用展開/摺疊呈現
- **高對比**：文字與背景對比度 ≥ 4.5:1
- **減少動畫**：避免複雜轉場，降低暈眩可能

---

## 2. 功能架構

### 功能一：單卡抽牌（MVP 核心）
```
輸入想問的問題 → 點選抽牌 → 顯示牌面 → 牌義解讀 → AI 解讀
```

### 功能二：牌陣模式（進階）
```
選擇牌陣 → 輸入問題 → 依序抽牌 → 牌陣圖展示 → 逐張解讀 → AI 統整
```

### 功能三：日記/記錄（儲存與回顧）
```
儲存每次抽牌結果 → 可寫心得 → 歷史記錄瀏覽 → 心情軌跡
```

## 5. SCRUM 開發階段規劃

每個 Sprint 結束時，都必須交付一個 **可運作、可展示、有價值的增量**。

每個 Sprint 包含：
- **Sprint Goal**：本衝刺的商業目標
- **Task Breakdown**：具體實作工作
- **Acceptance Criteria (AC)**：可驗證的通過條件（等同你說的「驗證項」）
- **Definition of Done (DoD)**：技術完成定義

### Phase 1：MVP 核心抽牌體驗

> 目標：使用者可以在手機上抽牌、看牌義、存記錄。
> 歷時：3 Sprints × 1 週 = 3 週

#### Sprint 1：單卡抽牌核心

| 項目 | 內容 |
|------|------|
| **Sprint Goal** | 使用者能完成「抽一張牌 + 看牌義」的最小閉環 |
| **Tasks** | ① 專案初始化（React + Vite + Tailwind）② 78 張牌資料結構（JSON）③ 單卡隨機抽取邏輯 ④ 牌面顯示元件（牌名、關鍵字、正/逆位）⑤ 大字型基礎主題 |

**Acceptance Criteria（驗證項）**：

| # | 條件 | 測試方式 |
|---|------|---------|
| AC1-1 | 進入頁面，看到一個明顯的「抽牌」按鈕 | 視覺確認 |
| AC1-2 | 點擊抽牌後，隨機顯示一張牌（78 張中任一） | 抽 10 次確認不同 |
| AC1-3 | 每張牌顯示：牌名、正位或逆位、對應關鍵字 | 逐一比對 JSON 資料 |
| AC1-4 | 牌面有正/逆位隨機翻轉（50% 機率） | 抽 20 次統計分佈 |
| AC1-5 | 畫面在 iPhone SE / Android 常見尺寸可正常顯示 | 瀏覽器 DevTools 測試 |
| AC1-6 | 所有文字大小 ≥ 18px | 開發者工具檢驗 |

## 7. 風險與對策

| 風險 | 影響 | 對策 |
|------|------|------|
| AI 解讀品質不穩 | 用戶體驗下降 | 內建牌義資料庫作為 fallback，AI 為輔助 |

| AI API 費用超支 | 成本失控 | 設定用量提醒、cache 常見問題解讀 |
